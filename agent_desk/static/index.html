    Tasks
    Dependencies & run behavior
    Tasks run after their selected dependencies succeed. Failed dependencies are skipped; cycles are rejected.
    One run per workflow at a time, up to four starting/running tasks across the scheduler. A scheduled tick during an active run is skipped. After sleep or downtime, one overdue run starts; missed ticks are not replayed in a burst.

            HARNESS ADAPTERS
            Bring your agents together.
            Codex, Claude Code, Grok, and OpenCode executables are discovered automatically. Their task and activity stay unknown until an adapter reports them.
            Any harness can report events to POST /api/events using the adapter token printed in the server terminal.
            {
  "id": "my-agent",
  "harness": "custom",
  "name": "Frontend agent",
  "task": "Build the settings screen",
  "project": "agent-desk",
  "status": "needs_input",
  "question": "Which color palette?"
}
            Another machine over SSH
            Remote sessions can report activity through the event API. If you already have SSH access from this Mac and forwarding is allowed, run this on your Mac, replacing your-ssh-host with your configured SSH alias:
            ssh -N -o ExitOnForwardFailure=yes \
  -R 127.0.0.1:4310:127.0.0.1:4310 your-ssh-host
            The remote adapter can then post to http://127.0.0.1:4310/api/events with the token from Agent Desk's server terminal. Use a distinct session ID and omit remote PIDs from local-process discovery.
            This does not attach Claude's interactive terminal; a Claude adapter is still needed for automatic activity and approvals.
            Use New terminal to launch an interactive harness and respond directly. Processes started elsewhere need their own terminal connection or a harness resume workflow. Adapter events and managed terminals are kept in memory.
